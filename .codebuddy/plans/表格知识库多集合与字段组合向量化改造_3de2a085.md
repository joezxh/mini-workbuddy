## 产品概述
对「表格知识库」做一次结构性改造：集合（kms_collection）支持定义多个字段并指定其中 1 个或多个字段组合为向量化内容；表格知识库下可配置多个集合；文档必须归属所属知识库下的某个集合并按其字段定义切分。

## 核心功能
1. **数据结构关系**
   - `kms_collection` 定义多个字段，并额外指定「1 个或多个字段组合」作为向量化内容，向量检索依赖该内容。
   - `kms_collection` 多对一 `kms_knowledge`：一个知识库可配置多个集合（仅表格知识库启用多集合，普通文档知识库维持 `kb_{kid}` 1:1）。
   - 表格知识库下的 `kms_document` **必选**所属知识库下的一个 `kms_collection`，按该集合字段定义切分并保存分段信息。
2. **表格文档切分分段**
   - 每段一行，遵守 CSV 格式（逗号间隔），一行一段。
   - 每段向量化内容 = 该集合配置的「字段组合」拼成的 CSV 行（content 与向量化文本一致）；未选中字段仅进 metadata 供过滤。
3. **表格知识库交互**
   - 上传文件列表点击后，展示该文件下的记录，字段按**文件关联集合**的字段定义动态渲染。
   - 上传时**未选择集合**：按文件记录格式自动生成字段定义（默认所有字段组合为向量化内容），后端自动新建该知识库下的集合承载该 schema。
   - 上传时**已选择集合**：按选中集合的字段定义校验文件列名与字段类型，不符则拒绝且不落数据。
   - 表格知识库新建时，字段设置**默认可留空**。


## 技术栈
- 后端：Python 3.11 + FastAPI + SQLAlchemy（同步会话）+ pgvector；迁移 Alembic（版本目录 `backend/alembic/versions/`，现有 `2026_09_11_0000-006_add_kb_tables.py`）
- 前端：Vue 3 + TypeScript + Ant Design Vue；i18n 四语（zh-CN / zh-TW / ja-JP / en-US）
- 复用现有原语：`table_schema.py`（schema_config 读写/推断/校验）、`content_service.parse_table`、`chunker_factory.build_table_row_chunks`

## 实现方案
**总体策略**：以「命名约定兼容 + 语义放宽 + 切分改写」三件事为核心，用最小改动面支撑多集合与字段组合向量化。

**关键决策（依据用户确认）**
1. **集合标识（方案 C，折中）**：仅表格知识库支持多集合。新集合命名 `kb_{kid}_{slug}`（保留 `kb_` 前缀），把 `resolve_knowledge_id` 的解析放宽为正则 `kb_(\d+)(?:_(.+))?`，使既有 8 处反查点（index_mode / pipeline_config / 路由 :301/:796 / collection_settings / agent_factory / table_schema / knowledge_factory / external_import）**无需改动**且 `kb_7 → 7` 仍成立。同时给 `kms_document` 增加 `collection_id`(BigInteger FK→kms_collection.id，可空) 显式表达「文档必选集合」。普通文档 KB 继续 `kb_{kid}`，行为不变。
2. **向量化字段多选**：沿用字段级 `embedding` 布尔但允许多选（向后兼容旧数据单个 True）；读取处由 `next(...)` 改为列表推导 `[f["name"] for f in fields if f.get("embedding")]`（改 `kb.py:1117/1145`）；自动生成时默认**全字段 embedding=True**。
3. **切分（方案 B）**：`build_table_row_chunks` 签名由 `embed_field: str` 改为 `embed_fields: list[str]`；`content` = 选中字段值按 RFC4180 CSV 规则拼接（含逗号/引号/换行需转义）；`metadata_` 存未选中字段 + `chunk_type="table_row"`；向量化文本 == content。
4. **未选集合自动建集合（方案 A）**：导入接口未指定集合时，为该知识库自动创建集合（名称 `kb_{kid}_{slug}` 自动生成）、把 infer 出的字段写入其 `schema_config`，文档 `collection`/`collection_id` 指向它。
5. **校验**：指定集合时复用 `resolve_import_schema` / `TableSchemaMismatch` 校验列名与类型（不符 422、不落数据）；并校验集合 `knowledge_id` 与文档 `knowledge_id` 一致（跨库集合拒绝）。

## 实现要点
- **性能**：集合 schema 读取为单表点查，可按 collection 名做短期缓存；切分仍是一次遍历 O(行数×字段数)，CSV 拼接用 `csv.writer` 逐行写入避免手写拼接错误。
- **日志**：集合自动创建、字段自动推断、校验拒绝均用 `logger.warning/info` 记录集合名与字段数，**不打印行数据**（避免大 payload / PII）。
- **回归控制**：`resolve_knowledge_id` 修改必须保证 `kb_7` 仍解析为 7；保持 QA / 多模态 / proxy / connector 等形态与 economy 模式行为不变；新列 `collection_id` 可空，保证旧数据不破坏。

## 架构设计
```mermaid
flowchart TD
    A[上传表格文件] --> B{是否指定 collection_id/名}
    B -- 否 --> C[按表头 infer 字段<br/>默认全字段 embedding=True]
    C --> D[自动新建 kb_{kid}_{slug} 集合<br/>写 schema_config]
    B -- 是 --> E[按集合 schema_config<br/>校验列名与类型]
    E -- 不符 --> F[TableSchemaMismatch 422<br/>不落数据]
    D --> G[build_table_row_chunks]
    E -- 通过 --> G
    G --> H[每行一段: content=选中字段CSV行]
    H --> I[kms_segment 落库 + 向量化]
    I --> J[kms_document.collection_id/name 指向集合]
```
集合命名始终保留 `kb_{kid}` 前缀，`resolve_knowledge_id` 正则放宽后，既有「按名反查知识库/维度/索引模式」链路零改动。
