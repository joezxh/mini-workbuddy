# MiniWorkBuddy - 前端工程

> 基于 Vue 3 + Vite + TypeScript + Ant Design Vue

## 技术栈

- **框架**: Vue 3.4 (Composition API + `<script setup>`)
- **构建工具**: Vite 5
- **语言**: TypeScript 5
- **UI 组件库**: Ant Design Vue 4
- **状态管理**: Pinia 2
- **路由**: Vue Router 4
- **HTTP 客户端**: Axios
- **图表库**: ECharts 5 + vue-echarts
- **日期处理**: Day.js
- **Markdown 渲染**: markdown-it

## 开发规范

### 组件命名
- 使用 PascalCase 命名组件文件
- 组件名称应具有描述性

### API 调用
- 所有 API 调用统一在 `src/api/` 目录下定义
- 使用 TypeScript 类型定义请求和响应

### 状态管理
- 使用 Pinia 进行全局状态管理
- 按模块划分 store

### 样式规范
- 使用 CSS 变量定义主题色
- 组件样式使用 scoped

## 环境变量

- `VITE_APP_TITLE`: 应用标题
- `VITE_APP_BASE_API`: API 基础路径
- `VITE_API_BASE_URL`: 后端 API 地址

## 浏览器支持

- Chrome >= 90
- Firefox >= 88
- Safari >= 14
- Edge >= 90

## 设计规范

### DESIGN.md 使用指南

项目维护了一份完整的设计规范文档 [`DESIGN.md`](./DESIGN.md)，所有前端开发必须严格遵守。

deisgn.md 生成提示词
```
请基于当前前端工程  @frontend   现有代码、全局样式、组件样式、布局规则，为项目编写一份标准 DESIGN.md，严格遵循 awesome-design-md 9段式规范，要求如下：
1. 整体原则：完全沿用项目已有的视觉、样式、交互规则，严禁凭空新增颜色、尺寸、圆角、阴影等设计属性，所有内容必须和现有代码保持一致。
2. 文档结构必须包含以下9个章节，顺序不能调整：
   - Visual Theme 视觉主题与设计理念
   - Color Palette 配色体系（使用表格展示：色彩类型、CSS变量/色值、Hex、使用场景，禁止硬编码无意义色值）
   - Typography 排版规范（全局字体、字号层级、行高、字重、使用场景）
   - Component Stylings 核心组件样式（梳理项目高频公共组件：按钮、输入框、卡片、弹窗、导航等，包含默认/hover/active/disabled 状态）
   - Layout Principles 布局原则（基准网格、间距体系、页面容器、模块间距规则）
   - Depth & Elevation 层级与阴影（阴影分级、z-index 全局规范）
   - Do's and Don'ts 设计准则（明确开发允许行为、强制禁止行为，结合前端工程规范）
   - Responsive Behavior 响应式规则（项目现有媒体查询断点、多端布局适配逻辑）
   - Agent Prompt Guide AI 编码指引（编写可直接使用的AI指令，指导后续编码严格遵守本 DESIGN.md）
3. 格式要求：标准 Markdown，多用表格、列表，结构清晰，方便AI后续解析读取。
4. 语言：使用中文编写，贴合国内前端团队使用习惯。
直接输出完整 DESIGN.md 全文，不要额外解释。
完成后更新README.md 文件，添加如何使用design.md的说明
```

#### AI 编码指引

当使用 Cursor、Claude Code 等 AI 编程工具时，建议在对话开始时提供以下指令：

```
请阅读 frontend/DESIGN.md 文件，严格遵守其中的设计规范。
在编写或修改 Vue 组件时：
1. 所有颜色必须使用 CSS 变量（var(--xxx)）
2. 圆角使用 2px/3px/4px/8px
3. 卡片必须包含 3px 高的 #1677ff 顶部装饰条
4. 过渡时间使用 0.2s/0.25s/0.3s
5. 响应式仅使用 1400px 和 768px 断点
6. 禁止引入新的设计变量

提示词范例:
# 提示词1：
生成组件并严格遵循 DESIGN.md 规范  
「
你是资深前端工程师，请基于项目根目录下的 `DESIGN.md` 规范，生成一个 [组件名称] 组件。
要求：  
1. 所有样式必须使用 `DESIGN.md` 中定义的 **语义化变量**（如颜色、间距、字体等）。  
2. 组件结构必须符合 **组件样式** 章节的规范（例如按钮的圆角、阴影层级）。  
3. 添加必要的 `aria-*` 属性以满足无障碍规范（若 `DESIGN.md` 中有定义）。  
4. 生成代码时需包含完整的类型定义和注释，并符合项目现有的代码风格规范。
```
