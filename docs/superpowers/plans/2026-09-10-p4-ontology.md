# P4 · 本体层实施计划（分层混合路线）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把当前**进程内内存单例**的 OWL 引擎改造为持久化、租户隔离的企业本体的底座，并在此之上交付可建、可评、可版本化的本体治理能力。

**Architecture:** P4.1 先把 `WikiOwlEngine` 从内存单例改为按租户读库（**这是修复缺陷，不是加功能**）。P4.2 借鉴 ontomind 的六表模型与 CQ 驱动的评审/版本流程。P4.3 通过 OWL 类标注 `kb_segment` 实现本体驱动的检索过滤。图谱构建 / 推理 / 溯源**明确延后**到 P4.4（可按需引入天枢，经 AgentScope MCP 挂载）。

**Tech Stack:** Python 3.11 / FastAPI / SQLAlchemy 2.0 / rdflib（已在用）/ Alembic / AgentScope 2.0.7 / pytest

**Spec:** `docs/superpowers/specs/2026-09-10-ontology-layer-design.md`
**依赖：** P4.1 无依赖（**可最先开工**）；P4.2 依赖 P2 原料；P4.3 依赖 P1

## 验收标准

| 项 | 标准 |
|---|---|
| **P4.1** | 重启不丢；租户 A 看不到租户 B 的本体；`/api/v1/wiki/owl/*` 全量回归通过 |
| TTL | 导入导出往返一致 |
| 校验 | 悬空父类 / 循环继承 / URI 冲突三类可被检出 |
| CQ | 覆盖度统计正确 |
| 候选 | P2 元数据 → 候选 → 人工接受 全链路可用；阈值与 P2 共用 |
| 版本 | 快照可查，回滚未启用 |
| P4.3 | 按 `class_uris` 过滤检索不越界 |

## 风险与退路

| 风险 | 退路 |
|---|---|
| **`WikiOwlEngine` 改造是行为变更** | Task 1 Step 5 强制全量回归 OWL 接口 |
| TTL 往返不保真 | 往返测试先写，不通过则改用"原样存储 TTL 文本 + 结构化索引"双轨 |
| P4.2 工作量膨胀 | 已拆为 Task 4（CRUD 与 CQ）与 Task 5（候选与评审），可分别交付 |
| 未来引入天枢的映射成本 | 数据结构贴近 W3C 语义（OWL/RDFS），已在 Task 3–4 体现 |
