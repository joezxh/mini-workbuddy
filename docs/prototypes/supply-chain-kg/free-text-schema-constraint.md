# 供应链场景 · KG 类型约束（自由文本方式）

> 用途：KG 知识库构建配置页（KgBuildConfig.vue）→「类型约束」选择 **自由文本（free_text）** 时，
> 将下方提示词整段粘贴进约束文本框。后端 `build_schema_hint` 会原样注入抽取 prompt。

## 一、可直接粘贴的约束提示词

```text
本知识库为「供应链」场景，抽取实体与关系时必须严格使用以下类型集合，不得自造类型，不得输出类型集合之外的实体或关系。

【实体类型】（仅允许这 10 类）
1. 部门   —— 公司内部组织单元，如：采购部、销售部、仓储部、品控部
2. 供应商 —— 向本公司供货的外部企业，如：华创制造、启明电子、恒信科技
3. 产品   —— 可销售的整机/成品，如：天枢服务器、智联数码、联影工作站
4. 物料   —— 生产投入的原材料与零部件，如：电芯、主板、结构件、包装材料
5. 仓库   —— 仓储节点，如：北京仓、上海仓、华南仓
6. 客户   —— 采购本公司产品的外部企业，如：星海科技、远航贸易
7. 订单   —— 采购订单或销售订单，如：PO-2026-031、年度框架订单
8. 物流   —— 运输/配送过程与单据，如：干线运输、冷链配送、发运批次 SH-092
9. 协议   —— 框架合同与合作协议，如：2026年度供应商框架协议、销售框架合同
10. 风险事件 —— 已发生或潜在的风险，如：断供、延迟交付、质量事故、价格波动

【关系类型】（仅允许这 15 类，格式：起点类型 —[关系]→ 终点类型）
- 供应：部门 → 供应商（部门接受供应商供货）
- 生产：供应商 → 产品（供应商生产该产品）
- 提供：供应商 → 物料（供应商提供某物料）
- 库存：产品 → 仓库（产品在仓库存有库存）
- 存储：物料 → 仓库（物料存放于仓库）
- 签约：部门 → 客户（部门与客户签署销售合同）
- 采购：客户 → 产品（客户采购该产品）
- 配套：产品 → 产品（两产品配套/组合销售）
- 代理：供应商 → 供应商（一方代理另一方产能或产品）
- 协作：部门 → 部门（部门间业务协同）
- 隶属订单：订单 → 客户 或 供应商（订单归属于某客户或某供应商）
- 包含：订单 → 产品（订单明细包含某产品）
- 承运：物流 → 仓库（物流运输至仓库）
- 覆盖：协议 → 供应商 或 客户（框架协议覆盖的合作方）
- 引发风险：供应商 或 物料 或 物流 → 风险事件（该主体/环节引发某风险）

【抽取纪律】
1. 实体 name 取文本中最完整的叫法；简称、代号、英文名写入 aliases，不要另建实体
   （例：「华创」「Huachuang」→ 归入「华创制造」的别名）。
2. 关系两端必须是已抽取的实体，禁止悬空边；方向按上文起点→终点，不得反向。
3. 数字、日期、金额、型号等属性写入 properties，不作为实体。
4. 「产品」与「物料」区分：成品可售→产品；生产投入件→物料；同一 SKU 双重角色时建两条实体并以「包含/配套」关联。
5. 文档中的流程图式描述（下单、审批、入库步骤）只抽取其中的主体与客体关系，不要把「步骤」建为实体。
6. 无法归入上述类型的候选，宁缺毋滥，直接丢弃。
```

## 二、与 CDM 方式的等价性说明

| 自由文本条目 | CDM 对应物 |
|---|---|
| 实体类型 10 类 | `meta_object_standard`（code=`sc.Supplier`…，name=中文类型名） |
| 关系类型 15 类 | `meta_object_relation`（name=关系名，from/to 指向对象标准） |
| 抽取纪律 | 无 CDM 对应（CDM 只约束类型集合；纪律段仅自由文本能携带） |

自由文本方式的优势是能把"别名归并、方向、丢弃原则"等纪律一并写进去；CDM 方式类型更权威（`build_schema_hint` 自动生成 `code(name)` 清单），但只有类型名本身。若二者同时需要：先用 CDM 落库保类型权威，再把本文件第一节"抽取纪律"追加进 free_text 做混合约束（当前配置页二者互斥，取其一）。
