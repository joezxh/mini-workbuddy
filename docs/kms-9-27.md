| 层面 | 问题 | 建议方案 | 性能增益 | 实现难度 |
|-----|------|---------|---------|----------|

| **租户隔离** | AgentScope mount 后 user_id 映射 | UserIdMapper 纵深防御 | 符合 P1 Spec §5 | 中 |[P1 KB Design §4](../specs/2026-09-10-kb-pgvector-design.md#4)|

### 4.4 性能提升方案（代码级实现）

#### 4.4.1 HNSW 索引迁移

```sql
-- backend/scripts/migrations/versions/hnsw_index.sql
ALTER TABLE kms_article DROP INDEX IF EXISTS idx_wiki_article_content_vector;
CREATE INDEX idx_wiki_article_content_vector_hnsw ON kms_article
USING hnsw (content_vector vector_cosine_ops)
WITH (m = 16, ef_construction = 64);
```

**验收指标**: 10 万文章量级 P95 检索延迟 < 100ms（参照 [P1 KB Design §3.5 实测](./superpowers/specs/2026-09-10-kb-pgvector-design.md#35)）。

## 5. 综合优化建议（v2 补充 AgentScope 整合）

### 5.1 功能覆盖率统计（精确到模块）

| 模块 | 后端完成度 | 前端完成度 | 核心缺失 | 评分 |
|-----|-----------|-----------|---------|------|
| **LLM Wiki** | 85% | 90%+ | 权限控制、HNSW 索引、Redis 缓存 | ⭐⭐⭐⭐☆ |
| **通用知识库** | 70% | 50% | SqlWorkbench 未实现、元数据单库硬编码 | ⭐⭐⭐☆☆ |
| **外部集成** | 5% | 40% | 所有后端 API 缺失（Notion/Dify/MVP） | ⭐⭐☆☆☆ |
| **本体整合** | 30% | 20% | ontomind 五层管道未落地（见 Ontology Spec） | ⭐⭐☆☆☆ |

**整体评估**: LLM Wiki 基础功能可用但性能未优化；通用知识库与外部集成严重落后于设计文档规划。

### 5.2 建议迭代顺序（对齐 Wiki 标准化计划）

**P0 (本周)**:

3. **[外部 KB]** Notion/Dify 连接器 MVP + REST CRUD（参照 [Yuxi 实现](https://xerrors.github.io/Yuxi/)）
4. **[RBAC]** Wiki/SQL/ExternalKb 三模块角色权限点注册

**P1 (下周)**:
