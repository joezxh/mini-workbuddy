## 三、功能对比（历史遗留 vs 现有实现）

基于历史会话记录，旧 `views/admin/llm-wiki` 中的页面为**不可达死代码**，且其子组件 `CategoryTab.vue` 引用的 API 函数（`getCategoryTree` / `updateCategory` / `deleteCategory`）在前端 `api/wiki.ts` 中并不存在，无法编译运行。

| 功能点 | 旧 `admin/llm-wiki`（已删/失效） | 现有 `kms/wiki`（可用） |
|---|---|---|
| 入口可达性 | 无路由、无 componentMap 注册，**死代码** | `/wiki` + `kg-private-kb` 控制台 Tab，**可达** |
| 分类树 | `CategoryTab.vue` 引用了不存在的 API，**损坏** | `index.vue` 内 `a-tree`，含知识库/分类节点、右键菜单、新建/重命名/删除 |
| 知识库管理 | 无（仅有占位 Tab） | 完整 CRUD（仅 wiki 类型）、知识库节点作为分类父节点、只读信息查看弹窗 |
| 文章列表/筛选 | 占位 | 左右两栏联动、按分类/知识库过滤、搜索、分页 |
| 文章编辑/查看 | 占位 | `ArticleEdit.vue` / `ArticleView.vue` |
| RAG 测试台 | `RagTestTab`（已迁出） | `RagTest.vue`（已迁入，含 7 个子组件） |
| 版本管理 | 无 | `VersionDiffView` / `VersionRollbackButton` / `VersionTimeline` |

**结论：两者不存在"重复且都有效"的功能。** 旧目录是早期未接线路由的废弃原型，功能已被 `kms/wiki` 完整覆盖并超出。

## 五、结论与建议

1. **无重复功能可合并**：`views/admin/llm-wiki` 已从工作区删除，仅余 `router/index.ts` 第 56 行注释。当前 Wiki 知识库的全部功能集中在 `views/kms/wiki`，是单一事实来源。
2. **建议清理项（可选，非必须）**：删除 `router/index.ts` 第 56 行中 "自 admin/llm-wiki/RagTestTab 迁移" 的历史注释，避免后续维护者误以为该目录仍存在。
3. **无需新增代码**：现有 `kms/wiki` 已覆盖分类、知识库、文章、RAG、版本管理等全部能力，且前端/后端/路由/菜单/国际化（4 语言 `kmsWiki.*` 键）一致，链路自洽。
